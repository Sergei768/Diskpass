# Diskpass

Генератор криптографически защищённых физических тегов для носителей информации.

Diskpass решает конкретную задачу: у вас есть архив из десятков физических носителей (HDD, SSD, LTO-ленты, флешки), и вам нужно подписать каждый из них, не указывая на этикетке, что на нём находится, чем оно зашифровано и какой пароль используется.

Программа генерирует короткий тег вида `HK-T1R-BAM-LK-XYQ`, который наклеивается на носитель. Владелец, имея доступ к собственной зашифрованной базе, может по тегу найти тип носителя, объём, описание содержимого, метод шифрования и соответствующую запись с паролем. Для постороннего наблюдателя метка выглядит как последовательность коротких кодов.

## Ключевые возможности

- **Генерация физических тегов** из пяти компонентов: тип носителя, объём, пользовательская метка содержимого, метод шифрования и соль диска.
- **Уникальная схема на базу:** при инициализации компоненты случайным образом переставляются (`5! = 120` вариантов); порядок сохраняется в параметрах базы.
- **Удобная регистрация:** добавление подключённых накопителей или ручной ввод, выбор допустимых ёмкостей для конкретного типа носителя, просмотр внутренних кодов.
- **Защищённое хранение:** локальная база `.dpdb` содержит метки, пароли, заметки и соответствия носителей; используется OpenPGP/GPGME и XChaCha20-Poly1305.
- **Поиск по архиву:** индекс файлов, сохранённые снимки каталогов, поиск в том числе по отключённым носителям; дополнительные снимки SMART при наличии `smartctl`.
- **Управление доступом:** GnuPG/pinentry при работе с приватным OpenPGP-ключом, блокировка по таймеру и очистка буфера обмена.
- **Расширения:** нативные плагины, включая модуль печати тегов Katasymbol E11 через Bluetooth LE; интерфейс — GTK3 для Xorg и Wayland.

## Формат тега

Тег состоит из пяти блоков, разделённых дефисами. Порядок блоков задаёт индивидуальная схема, сгенерированная для конкретной базы.

<img src="diagrams/tags.svg" width="100%" alt="Схема формирования физических тегов Diskpass">

| # | Компонент | Описание |
|---|---|---|
| 1 | `type` | Тип физического носителя: HDD, SSD, USB, LTO и др. |
| 2 | `size` | Объём накопителя, записанный внутренним кодом |
| 3 | `content_tag` | Пользовательская метка содержимого |
| 4 | `cipher` | Метод шифрования данных на носителе |
| 5 | `dsalt` | Случайное значение, назначенное конкретному носителю |

Каждый блок имеет вид **`[КОД][КОНТРОЛЬНЫЙ_СИМВОЛ]`**. Последний символ вычисляется с использованием **BLAKE2b**, секретного `noise_key` и `salt` базы; это проверочный символ, а не самостоятельное шифрование блока.

### Алгоритм генерации тега

1. **Схема базы.** При создании базы выбирается случайная перестановка пяти компонентов, которая сохраняется для последующих записей.
2. **Кодирование данных.** Тип носителя, объём, пользовательская метка и метод шифрования преобразуются в короткие внутренние коды по словарям Diskpass.
3. **Соль диска.** Для каждого носителя создаётся собственное случайное значение `dsalt`.
4. **Контрольные символы.** Для каждого блока вычисляется однобуквенный проверочный суффикс с использованием секретных параметров базы.
5. **Сборка.** Блоки размещаются в порядке схемы и объединяются дефисами.

### Пример

Тег `HK-T1R-BAM-LK-XYQ` при порядке `type-size-content-cipher-dsalt`:

| Блок | Код | Контрольный символ | Значение |
|:---:|:---:|:---:|---|
| `HK` | `H` | `K` | Тип носителя: **HDD** |
| `T1R` | `T1` | `R` | Объём: **1 TB** |
| `BAM` | `BA` | `M` | Метка: **Backup** (пользовательская) |
| `LK` | `L` | `K` | Метод шифрования: **LUKS** |
| `XYQ` | `XY` | `Q` | Соль диска: **XY** |

### Схемы кодирования

**Тип носителя (`type`):** один символ. `H` — HDD, `S` — SSD, `U` — USB, `M` — M.2, `D` — SD, `C` — CF, `O` — OPTICAL, `X` — OTHER. Поколения LTO кодируются цифрами `1`–`9`; значения объёма подбираются с учётом поколения ленты.

**Шифр (`cipher`):** `L` — LUKS, `V` — VeraCrypt, `B` — BitLocker, `7` — 7-Zip, `A` — Age, `G` — GPG, `N` — NONE.

Тег предназначен для компактной идентификации носителя; подробное содержимое, пароль и связь между кодами и записями хранятся в зашифрованной базе.

## Шифрование базы данных

<img src="diagrams/encryption.svg" width="100%" alt="Схема шифрования базы DPENV5">

База `.dpdb` содержит описание носителей, их метки, пароли, заметки, параметры схемы и сохранённые индексы файлов. При сохранении данные сериализуются и помещаются в зашифрованный **бинарный контейнер DPENV5**.

1. **Сериализация:** структура записей формируется с использованием `cJSON`.
2. **Симметричное шифрование:** **XChaCha20-Poly1305** защищает содержимое базы и проверяет его подлинность (AEAD). Внешний заголовок включается в AAD; применяются одноразовый `nonce` и аутентифицированное дополнение.
3. **Ключевой конверт:** **OpenPGP/GPGME** защищает ключевой материал и использует внешний GnuPG/pinentry для операций с приватным ключом. Совместимый движок GnuPG поддерживает профиль **ML-KEM/Kyber**.
4. **Подпись:** формат DPENV5 связывает OpenPGP-подпись с **BLAKE2b-256-хешем дополненных исходных данных**. При открытии проверяются подпись, получатель, параметры и аутентичность содержимого.
5. **Целостность версий:** цепочка версий и локальное состояние *anti-rollback* помогают обнаруживать откат сохранённой базы к устаревшему состоянию.

**Argon2id** используется отдельно для хеширования цифрового кода режима калькулятора и защиты локальных настроек; он не заменяет OpenPGP и XChaCha20-Poly1305 при хранении `.dpdb`.

Для ML-KEM необходимы **GPGME ≥ 1.24.1** и совместимый движок GnuPG. При смене OpenPGP-ключа перешифровывается текущая база; старые резервные копии остаются связанными с прежним ключом.

## Стеганография

<img src="diagrams/steganography.svg" width="100%" alt="Алгоритм стеганографического хранения базы Diskpass">

Diskpass позволяет встроить **уже зашифрованную `.dpdb`** в медиафайл. Приложение определяет формат файла-носителя, проверяет вместимость, встраивает полезную нагрузку в отдельный файл и затем может извлечь базу для штатной расшифровки через OpenPGP.

| Формат | Метод встраивания |
|---|---|
| PNG, BMP, TIFF, lossless WebP и некоторые другие изображения | Младшие биты RGB-пикселей (LSB) |
| JPEG | Чётность выбранных квантованных AC DCT-коэффициентов |
| WAV (integer PCM) | Младший бит PCM-сэмпла |
| MP3 | Существующая обложка APIC (ID3v2); аудиокадры не изменяются |
| FLAC | Встроенная обложка PICTURE; аудиофреймы не изменяются |

В новых форматах **bootstrap seed** вычисляется из устойчивых данных файла-носителя. Это позволяет обнаружить и извлечь зашифрованную базу до её разблокировки; ключ OpenPGP при этом по-прежнему требуется для чтения содержимого.

При работе непосредственно со стегофайлом Diskpass создаёт временную зашифрованную `.dpdb` и после успешного сохранения повторно встраивает обновлённый контейнер. Ограничение нагрузки задаётся `DISKPASS_STEGO_MAX_PERCENT`: допустимо **1–40**, по умолчанию **20%**.

## Архитектура и реализация

Diskpass написан на **C11** и использует:

- **libsodium** — случайные значения, защищённое выделение памяти и очистку чувствительных буферов;
- **GPGME / GnuPG** — управление OpenPGP-ключами, конвертами и подписями;
- **cJSON** — сериализацию структуры базы;
- **GTK3 / GLib** — графический интерфейс и системные события;
- **libjpeg / libwebp** — обработку графических форматов в подсистеме стеганографии.

Плагинный интерфейс **Diskpass Plugin ABI v1** позволяет добавлять действия в меню приложения. Например, модуль **Katasymbol E11** использует BlueZ/Bluetooth LE для печати этикеток. Нативные `.so` загружаются после разблокировки базы и подтверждения доверия.

## Сборка и установка

**Debian / Ubuntu — зависимости:**

```bash
sudo apt install build-essential pkg-config libgtk-3-dev libglib2.0-dev \
  libgpgme-dev libsodium-dev libcjson-dev libjpeg-dev libwebp-dev
```

**Сборка без установки:**

```bash
git clone https://github.com/Sergei768/Diskpass.git
cd Diskpass
make -j2
./diskpass
```

**Пользовательская установка:**

```bash
# Для установщика и плагина печати могут понадобиться дополнительные пакеты:
sudo apt install libpango1.0-dev liblzma-dev imagemagick bluez fonts-dejavu-core
./build.sh
```

Запускайте `build.sh` **обычным пользователем**, не через `sudo`. Для отладочной сборки доступны `make debug` и `make clean`. Пакеты DEB, RPM, Arch, AppImage, tar и BSD собираются отдельным сценарием `diskpass-package.sh` при наличии подходящих инструментов.

## Модель нарушителя и особенности защиты

Diskpass проектировался для архива физических носителей, на которые нанесены короткие идентификаторы. **Рассматриваемый противник** — пассивный наблюдатель, имеющий доступ к носителю и его тегу, но не располагающий секретными параметрами базы и приватным OpenPGP-ключом. Он может сравнивать метки, изучать повторения и проводить структурный анализ.

**Свойства решения:** короткие внутренние коды и случайный порядок компонентов уменьшают количество непосредственно читаемой информации на этикетке. Контрольный символ BLAKE2b позволяет проверять блок при наличии параметров базы. **Конфиденциальность паролей и подробных описаний обеспечивается шифрованием `.dpdb`**, а не самим тегом.

**Границы применения:**

- Физический тег — псевдонимизированные метаданные, **не шифротекст**: повторяющиеся значения и длины блоков потенциально допускают частотный анализ.
- Diskpass не шифрует содержимое HDD, SSD или ленты; для этого используется отдельное ПО, например LUKS либо VeraCrypt.
- GnuPG/pinentry управляет запросами доступа к ключу; повторный запрос пароля при каждом открытии зависит от настроек агента и кэширования.
- Стеганография не гарантирует необнаружимость: LSB и DCT-встраивание могут оставлять статистические признаки, а преобразование медиафайла способно повредить вложение.
- Компрометация рабочей станции или приватного OpenPGP-ключа выходит за пределы защиты приложения; нативные плагины выполняются без песочницы.
- В DPENV5 могут быть видимы идентификаторы получателей OpenPGP. Старые DPENV4 и новые DPENV5 имеют разные свойства проверки подписи и требования к миграции.
